# Wireless CarPlay Maps V3.1

## 功能安装修订 / Feature-installation correction

MU1367 实机反馈显示菜单注册已成功、129 个文件清单通过，但功能安装在 `feature-transaction.sh` 第 21 行停止。原因是自定义 `hash()` 与 QNX ksh 默认别名冲突。此前只用 Linux sh 的测试没有覆盖该差异；现在保留脚本全部事务逻辑，仅将该函数及全部调用改为 `wmaps_file_hash`。QNX 6.5 SDK 自带 PD KSH 能复现旧错误，新脚本另行做完整语法及事务回归，不把这些主机测试称为实机安装成功。

已经安装绿色菜单入口的用户：重新下载完整 SD 安装包并替换本项目介质文件，保持手机断开和稳定供电，先选择 **Update this management entry only**，成功后再选对应仪表的安装项。必须见到 `WMAPS_FEATURE_COMMIT_OK` 及全部校验通过后再手动重启。此问题不要求卸载菜单或反复重做原车软件更新注册。作者提供的 `metainfo2.txt`、CRLF、目录校验以及全部原生音视频／地图／菜单程序不变。

Hardware feedback on MU1367 shows successful manager registration and a valid 129-file manifest, followed by a line-21 parser failure in `feature-transaction.sh`. The custom `hash()` name conflicts with a default QNX ksh alias. Earlier Linux-sh tests missed this difference. Only the function and its calls are renamed to `wmaps_file_hash`; transaction behavior is preserved. The QNX 6.5 SDK's PD KSH reproduces the old failure. Candidate syntax and transaction regression are separate host checks, not hardware-installation acceptance.

For an already registered manager, download the new complete SD installer, disconnect CarPlay and maintain power. Choose **Update this management entry only**, then install the correct cluster profile. Reboot manually only after `WMAPS_FEATURE_COMMIT_OK` and all checks pass. Do not uninstall or repeat native SWDL registration for this script error. The author's metadata, CRLF, directory checksum and native video/audio/map/menu programs remain unchanged.

## 安装包修订 / Installer repack

- 采用作者提供的 `metainfo2.txt` 原始字节，使用 Windows CRLF；头部 `MetafileChecksum` 与原签名前缀匹配，签名及其校验数字不擅自改写。
- 保留作者给定的 `FinalScriptName = "Final Script"`、`[scripts\final\Dir]` 和 `DownloadGroup = "Wireless CarPlay Maps"`；脚本介质路径仍为 `install/scripts/final/finalScript.sh`。
- 目录校验按作者的 7-Zip `SHA1 for data` 方法计算，包含脚本及 `hashes.txt`，结果为 `f98e4c9162f089363b6a8d6c92cd40112ba902a1`。先前误用了 `hashes.txt` 单文件哈希，现已纠正；不采用包含文件名的另一种目录结果。
- 按最终文件更新包内清单与下载校验，补充 LF／混合换行、错误头部、错误目录算法等拒绝测试。无线、地图、菜单和安装／恢复程序不改动；离线检查不代表我们的原车更新入口已实机验收。
- 请重新下载本页的 `Wireless_CarPlay_Maps_Standalone_v3.1.zip` 与 `SHA256SUMS.txt`，解压后完整替换 SD 卡上的本项目文件，勿只覆盖 `metainfo2.txt` 或混用旧包。

The V3.1 installer now preserves the author's metadata file byte-for-byte, including Windows CRLF and its original signed prefix. The supplied `Final Script` label, `[scripts\final\Dir]` descriptor and spaced download-group label are retained. The media script remains at `install/scripts/final/finalScript.sh`.

The directory checksum is verified against 7-Zip's `SHA1 for data` over the complete final directory, including the script and `hashes.txt`: `f98e4c9162f089363b6a8d6c92cd40112ba902a1`. The previous package incorrectly used the SHA-1 of `hashes.txt` alone. The separate data-and-names result is not used. Package/download manifests are refreshed, and negative tests cover invalid line endings, signed headers and the previously mistaken directory algorithm.

Only packaging and documentation change; wireless, map, menu and install/restore programs remain byte-for-byte unchanged. Earlier offline checks did not cover these complete metadata relationships. Native software-update acceptance still requires a hardware retest. Download this page's Standalone ZIP and checksum list again, and replace the project's complete SD contents without mixing an earlier package. Do not replace only `metainfo2.txt`.

## 中文安装步骤

1. 核对支持的精确固件及仪表，准备完整系统备份与恢复通路。不要跳过“不支持”提示。
2. 车辆停稳，持续稳定供电，完全断开手机的 USB 与无线 CarPlay。工程／绿色菜单应已可用；本包不代替开启工程模式。
3. 下载 V3.1 Standalone ZIP，按 `SHA256SUMS.txt` 校验后解压。
4. 把 `SD_ROOT` 内所有内容复制到 SD 卡根目录，保持目录完整，不多套一层文件夹。
5. 在原车软件更新入口选择 SD 介质，先完成独立管理入口注册。此步不是刷完整固件，也不等于功能已经安装。
6. 进入绿色菜单 **Wireless CarPlay Maps V3.1**：790 选择 AID 10.5 项，791 选择 AID 12.3 项，仍以精确固件核对结果为准。
7. 等待 `WMAPS_FEATURE_COMMIT_OK` 及全部校验成功，再手动完整重启，之后连接手机验收。失败先保存日志，不反复安装、不删除备份。

已安装前代版本时，使用新的完整 V3.1 介质，先选 `Update this management entry only`，再选 `Update installed Wireless CarPlay Maps`。恢复使用 `Restore saved first baseline - keep this entry`；需要移除入口时选择 `Restore baseline and remove this entry`。首次基线可能是安装前的旧公开版本，不一定是原厂。不要再运行旧 SD 的卸载脚本。

## Installation in English

1. Check the exact supported firmware and cluster. Keep a full system backup and recovery path. Never bypass an unsupported-target refusal.
2. Park safely, maintain reliable power and disconnect both USB and wireless CarPlay. Engineering/green-menu access must already be available; this package does not enable it.
3. Download the V3.1 Standalone ZIP, verify it with `SHA256SUMS.txt`, then extract it.
4. Copy everything inside `SD_ROOT` to the card root without an extra outer folder. Preserve all directories and files.
5. Select the SD medium in the native software-update interface and register the independent manager first. This is not a full firmware flash or completion of feature installation.
6. Open **Wireless CarPlay Maps V3.1** in the green menu. Choose AID 10.5 for 790 or AID 12.3 for 791, subject to the exact firmware gate.
7. Wait for `WMAPS_FEATURE_COMMIT_OK` and all checks to succeed. Fully reboot manually before connecting the phone. Preserve logs on failure; do not repeatedly reinstall or delete backups.

To upgrade a predecessor, use the new complete V3.1 media and choose `Update this management entry only` before `Update installed Wireless CarPlay Maps`. Restore with `Restore saved first baseline - keep this entry`; use `Restore baseline and remove this entry` to restore and remove the manager. The first baseline may be an older public installation rather than factory state. Do not use an old SD uninstaller.

## 菜单仪表识别修订 / Menu cluster identification

发布核对发现旧菜单可能把产品版本文件误当成仪表型号。V3.1 改为优先读取独立的 `PROFILE` 并核对确认值，保留真实旧仪表标识的兼容，拒绝未知和冲突配置；九十二项识别检查通过。只替换 MU1102 菜单中的对应分类辅助类，其他类及原生接收、地图、缩放程序不变。

An older menu could mistake a product version for cluster identity. V3.1 prioritizes the dedicated `PROFILE`, checks confirmed identity, retains genuine legacy identifiers and rejects unknown/conflicting inputs. Ninety-two identification cases pass. Only the relevant MU1102 menu helper class changes; other members and native receiver/map/zoom programs remain unchanged.
